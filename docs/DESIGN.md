# Rind 设计文档

面向想改它、想学它、或者想知道「为什么是这样」的人。技术分层与数据流在 [ARCHITECTURE.md](ARCHITECTURE.md)，
这里讲产品与交互上的取舍。

## 1. 它是什么，不做什么

Rind 是一个 macOS 卸载与清理工具：卸载一个 App 时，把它散落在 `~/Library` 各处的残留一起找出来，
**逐个说明每个文件为什么属于它、有多大把握**，再一起移进废纸篓。

**目标**

- 让「这个文件为什么会被删」在动手之前就看得见。
- 让每一次移动都能撤回（History 一键放回）。
- 拿不准的时候不动手，并说清哪里拿不准。

**非目标**

- 不是杀毒 / 反恶意软件，不做实时防护。
- 不做常驻后台监控（没有守护进程盯着你的文件）。Rind 只在你按下按钮时工作。
- 不做需要联网的功能：没有账号、没有遥测、没有云规则。
- 不碰系统级安装（macOS 更新、SIP、`/System`）。
- 不替你「一键优化」：能自动做的只有判断，动手前一定给你看计划。

## 2. 四条设计原则

1. **可解释。** 每一条候选都带 `Evidence`（证据：bundle id、内嵌组件、App Group、签名 Team、名称、规则库、
   pkg 回执、孤儿信号……）和 `Confidence`（certain / likely / possible）。界面上它们就是「为什么算它的」那一行。
2. **可撤销。** 所有删除只到废纸篓，History 记下它在废纸篓里的实际位置。唯一的不可逆操作是「清空废纸篓」，
   那是用户自己在 Finder 里做的，Rind 不代劳。
3. **保守默认。** 默认勾选 = 确定/很可能 + 没有别的 App 共用 + 大小已知 + 不在保护区 + 不在运行。
   其余一律列出但不勾。清理类的「重建代价高」（IDE 索引、浏览器内核下载、包管理器仓库）也是只列不勾。
4. **预演就是真跑。** `--dry-run` 走同一套检查：会移走的、会拒绝的、能释放多少，两边逐项一致。
   界面上的「确认」对话框展示的就是这份计划。

## 3. 信息架构

侧栏固定 228px，分三组：

```
总览                       ← 唯一的入口页：磁盘、智能扫描、各页入口

卸载与清理
  App      卸载 App 与残留
  孤儿     已删除 App 留下的文件
  清理     缓存 / 日志 / 包管理器 / 构建产物
  空间     谁最占地方 + 大文件
  启动项   LaunchAgents / LaunchDaemons

底部
  History  移走过什么、放回去
  设置     外观、语言、清理偏好、保护清单
```

为什么是「总览 + 五个动作页」而不是按对象分（App / 文件 / 服务）：用户每次坐下来，心里想的都是
「腾点地方」，而不是「我要处理孤儿残留」。总览回答「现在能腾多少」，具体页面回答「从哪儿腾」。

## 4. 页面职责与关键交互

### 总览

- 顶部：磁盘容量条（`disk::usage`，总 / 已用 / 可用）。
- 中部：**智能扫描**——一次跑孤儿 + 清理两类扫描，汇总成「能释放多少」。可以中途取消，已扫到的部分照常展示。
- 底部：各页入口卡片。扫描结果只读，不会顺手把勾选状态改掉。

### App

- 列表按名字排序，每行是图标 + 名字 + 版本 + 大小 + 来源（App Store / Homebrew / 未知）。
- 点进去是「这个 App 留下的东西」：每一项有路径、大小、理由、置信度。
- 保护区里的项不显示勾选框，只显示原因；需要管理员权限的项同样不可勾。
- 底部工具条固定显示「已选 N 项 · 共 X MB」和主按钮；执行前弹确认框，列出会移走的、拒绝的、能释放的。

### 孤儿

- 按「原来的 App」分组，组标题写清主人是谁、为什么认为它不在了（Spotlight 查不到、磁盘上没有、cask 已卸载……）。
- 刚被拖进废纸篓的 App 不算「已安装」，这是最常见的用法。
- Spotlight 不可用时整份结果降级：全部封顶为「可能」，不预先勾选，顶部给一条提示说明为什么。

### 清理

- 按类别分组（应用缓存 / 日志 / 浏览器缓存 / Xcode / 包管理器 / 构建产物 / 需要人判断的）。
- 「需要人判断的」从不建议；构建产物要有旁证文件（`target` 旁边有 `Cargo.toml`……），项目超过 `--min-age` 天才建议。
- 属主正在运行的，标「在用」，不勾。
- 项目根目录可以在设置里加减（默认 `~/work`、`~/Projects`、`~/Developer` 等）。

### 空间

- 树只到 `--depth` 层、每层前 N 项，其余折叠成「（其它）」；想往深处看就对子目录再分析一次。
- 右侧/下方是大文件清单。
- 里面埋着照片 / 音乐库或带钱包 profile 的目录**整个不可选**，并写明「里面有不能动的东西：<路径>」——
  不这样做的话，移走外层会把它们一起带走。
- 没来得及核实的节点按「不可选」处理（宁可多拦）。

### 启动项

- 一行一项：label、程序、是否孤儿、运行状态（来自 `/bin/launchctl`）、是否 RunAtLoad / KeepAlive。
- 只有当前用户域可操作；停用 / 启用是可逆的（`launchctl disable|enable`），移除是 bootout + plist 进废纸篓。

### History

- 一次移动是一行（卸载 / 孤儿 / 清理 / 文件 / 启动项），点开是清单。
- 「放回」是整批操作，逐项报告：跳过的项说明原因（不在废纸篓了、原处已经有东西、位置 History 放不回去）。

### 设置

- 语言（中 / 英，会记住：存在 `<data-dir>/language`）、清理偏好（项目根目录等）。
- **保护清单**只读：列出来的东西任何设置都不能覆盖。把它放在设置页是为了回答「你保证不动什么」。

## 5. 视觉与文案

- **颜色只有语义**：`Primary`（强调 / 主按钮）、`Info`、`Success`、`Warning`（在用、拿不准）、
  `Danger`（拒绝、危险动作）、`Neutral`（说明）。含义固定，不为了好看换用途。
- **深浅色是一等公民**：界面颜色都走主题 token（gpui-component 的 `Theme`），只有字母头像的底色白字
  这类装饰色是特意手调的固定值；
  支持「跟随系统 / 浅色 / 深色」三档，强制某一档时用 `App::set_window_appearance` 让原生窗口边框与
  标题栏一起切换，不留一块颜色对不上的角落。设置页的选择会落盘（`<data-dir>/appearance`）。
- **组件是同一套**：页头、卡片、图标块、进度条、置信度标签、提示条、空状态、统计块、底部工具条都由 `ui.rs`
  提供，页面只组合，不各自发明样式。
- **空状态永远说下一步**：不是「没有数据」，而是「没有找到孤儿残留——已删除的 App 通常最多」这类可行动的话。
- **进度可见、可取消**：扫描给出当前阶段与已看过的数量，长任务旁边就有取消按钮。
- **文案风格**：中文优先，平实英语式的短句，不用术语。说清后果（「放进废纸篓，清空之后才真正释放空间」），
  不用感叹号，不吓唬人，也不哄人。
- **双语覆盖**：所有枚举、按钮、错误都用 `rind-i18n` 的 key，测试保证中英两版都填满。

## 6. 数据流（界面一侧）

```
GPUI 界面 ──(background_executor)──▶ rind-core（同步 API + rayon）
     ▲                                    │
     └──── ScanProgress 回调（扫描进度 / 当前阶段）────┘
```

- core 的类型都是 `Send + Sync + Clone + Serialize`：界面、CLI、`--json` 共用同一份。
- 扫描在后台执行器里跑，界面只收进度回调；取消通过共享的 `cancel` 标志。
- 界面和 core 之间隔了一层 `Services`：真实模式调 core，`RIND_DEMO=1` 时换成内存里的示例后端，
  所以整条交互可以在不碰系统的情况下走一遍。

## 7. 扩展点

| 想加什么 | 从哪儿开始 |
| --- | --- |
| 给某个 App 补清理路径 | `rules/<bundle-id>.toml`（只能补充证据，不能绕过保护区） |
| 新的清理类别 | `cleanup.rs` 的 `CleanupCategory` + i18n 的类别文案 + 设置页的说明 |
| 新的卸载证据 | `matcher.rs` 的 `EvidenceKind` + 打分规则 + i18n |
| 新页面 | `model.rs` 的 `Page` + `*_page.rs` + 侧栏；数据从 `Services` 走 |

加任何一类「会移动东西」的功能，都要走唯一出口 `remove::trash_items`（见 [SAFETY.md](SAFETY.md) 第 2 节）。
